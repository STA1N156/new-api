# 邀请计划

- 注册奖励沿用 `QuotaForInviter`（邀请人）与 `QuotaForInvitee`（好友），页面展示当前配置；为 0 时不赠送注册奖励。
- 好友新完成的余额充值和兑换码兑换，按实际到账原始额度的 **8%** 额外奖励给直接邀请人。好友全额到账，不递归分成；不足一个原始额度单位的部分向下取整。
- 通过支付通道购买订阅也发放 **8%**：订单保存的支付金额 ÷ 结算时的充值单价 `Price` × `QuotaPerUnit`，折算为原始额度后计算奖励。不使用 `USDExchangeRate`、套餐周期额度或后来修改的套餐价格。充值单价为 1、每 USD 对应 10🍪 时，支付 ¥600 对应 **480🍪** 奖励；自定义货币兑换率只影响奖励的显示。
- 易支付、Stripe、Creem、Waffo、Waffo Pancake 和管理员充值补单的现有充值入口，以及订阅支付完成和兑换码兑换，共用奖励计算。来源订单/兑换码的锁、状态检查、到账或订阅开通、邀请奖励和奖励快照在同一个事务内，重复提交不会重复发放，任一步失败全部回滚。
- 已完成订单不补发，原先按 5% 发放的奖励保留原金额。现有邀请关系适用于上线后新完成的交易；余额兑换订阅、管理员直接绑定订阅/修改余额、邀请奖励转余额不计入返奖励，避免内部余额流转重复奖励。
- 延续原有支付合规开关。未确认时不发邀请奖励；已删除或不存在的邀请人不参与奖励，也不影响好友充值。

## 收入与兼容

`aff_quota` 为可用奖励，`aff_history` 为累计收入，`aff_topup_quota` 为累计交易奖励（充值、支付订阅、兑换码），继续展示在“充值收益”。邀请注册收入 = 累计收入 − 累计交易奖励。旧收入保留并归入邀请注册收入。

奖励累计字段使用有溢出检查的 BIGINT，避免持续获得分成后超出旧 INT 字段范围；数据库启动迁移会拓宽旧字段并添加默认值为 0 的新字段。`top_ups.reward_inviter_id` 和 `reward_quota` 保存充值与支付订阅的奖励快照；兑换奖励保存到 `redemptions` 的同名字段，历史兑换码默认值为 0。

可用奖励需通过“转入余额”后消费，转入不改变累计收入或充值收益；延续原有最低转入额度，并校验钱包上限和同步余额缓存。邀请人数按实际邀请关系统计，修复旧版注册奖励为 0 时不计数的问题。

## 验证

`model/invitation_test.go` 覆盖各充值入口、重复回调、事务回滚、舍入、大额计算、失效邀请人和奖励转余额。`model/invitation_sources_test.go` 覆盖支付订阅、并发重复回调/兑换、钱包及奖励溢出的回滚，以及余额兑换和管理员绑定不发奖励。`controller/invitation_test.go` 与前端邀请卡片测试保护页面所需的收入和规则信息。
