# 2026 双节活动

- 活动时间：2026-09-25 00:00:00（UTC+8）至 2026-10-08 00:00:00（UTC+8），结束边界不包含。
- 活动期间成功到账的在线充值和兑换码额度累计参与。每累计到 500 / 1000 / 2000 / 3000 / 4000 / 5000 / 6000 / 7000🍪，分别新增 1 / 2 / 2 / 3 / 3 / 3 / 3 / 3 次机会，每档一次，总计最多 20 次。
- 按实际到账额度统计；一笔到账可以跨越多个档位，小数额度正常累计。支付价格、历史余额、订阅购买、邀请奖励转入和抽奖奖励不计入。
- 本活动固定使用当前饼干口径：1🍪 = 50,000 内部额度（1 USD = 10🍪）。门槛和奖励均固定，不随之后的显示汇率调整；活动上线后不应改变此口径或概率。
- 奖品及概率：50🍪 55.0%、100🍪 35.0%、200🍪 5.0%、300🍪 2.5%、500🍪 1.5%、1000🍪 1.0%。独立抽奖，不设保底次数。
- 仅赠送机会，不出售抽奖次数。活动结束后不能使用剩余机会，已到账奖励保留。
- 侧边栏“常规 / 双节活动”保留入口；钱包“添加余额”上方仅在活动期间显示入口。活动开始前页面锁定并模糊背景，显示天、小时、分钟倒计时；到点自动解锁，结束后重新锁定并显示活动已结束。时间以服务器返回值校准。
- 抽奖记录在电脑端位于转盘下方，手机端位于奖品与概率下方。

## 数据与重试

`FestivalCredit` 在充值/兑换原事务内保存实际到账额度，按活动、来源类型和来源 ID 唯一。重复支付回调或同一兑换码不能重复计数，授信失败时活动进度一同回滚。

`FestivalDraw` 保存中奖结果和实际入账额度。后端使用加密随机数，在用户行锁内检查时间与次数；中奖记录和钱包授信在同一事务完成。每用户活动内的抽奖序号和请求 ID 均有唯一约束，兼容 MySQL、PostgreSQL 和 SQLite。

前端在请求前保存请求 ID。网络中断后重试使用相同 ID；刷新后可从个人记录恢复已经完成的结果。动画只展示服务器结果，不决定实际奖品。中奖奖励直接走钱包授信，不触发充值活动进度或邀请返奖。

历史记录不自动回填，应在活动开始前部署所有处理充值和兑换请求的实例。统计接口只返回当前登录用户的记录；活动时间由服务器判断，不接受客户端时间或奖品。
